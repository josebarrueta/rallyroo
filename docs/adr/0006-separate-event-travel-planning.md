# Model Event travel planning as a separate deep module

Rallyroo will keep an optional arrival target on Event but model route inputs, calculated leave guidance, and leave-alert delivery in a separate Travel plan and deep Travel Planning module. The first adapter will use Google Routes for server-side traffic-aware driving estimates, while Event saves and fixed Event alerts remain available during provider failure. Initial plans require an explicit origin and eligible recipient; calendar and routine inference may only suggest origins with provenance and confirmation, and Rallyroo will not retain passive location history. This preserves Event semantics, allows dynamic estimates to be reconciled independently, and avoids making provider-derived state authoritative Family schedule data.
