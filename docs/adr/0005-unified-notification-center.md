# Unify notification intents, member inboxes, and channel delivery

Rallyroo will use a deep Notification Center module for Event occurrence alerts, Reminder occurrence alerts, immediate schedule updates, Commuter disruptions, driver assignments, and saved conflict warnings. Producers submit a typed intent with a stable deduplication key, authorized recipient member IDs, protected presentation details, and an opaque typed destination. The module atomically materializes one member inbox record and its eligible channel-delivery work per recipient; callers do not resolve device tokens, construct APNs payloads, or manage retries.

A member inbox record is durable user-visible state, not evidence that APNs succeeded. Channel delivery has separate pending, claimed, delivered, no-recipient, and terminal-failure state. APNs and on-device local scheduling are the two real delivery adapters. Remote and local Notification Center stores are the two client persistence adapters. Read/unread state belongs to each member and synchronizes independently of delivery state.

Recipient resolution remains at the privacy-owning producer seam: Event participants, Reminder assignees, assigned drivers, personal commute owners, or authorized Family audiences. The module deduplicates a member reached through multiple roles and never broadens an audience during retry. Immediate schedule updates remain distinct from occurrence alerts, exclude the saving member where specified, and summarize recurring-series changes once.

PostgreSQL stores opaque routing identifiers, trigger instants, categories, statuses, and SHA-256 deduplication digests as queryable metadata. Titles, bodies, destination details, and other descriptive Family data are encrypted with the existing per-Family envelope-encryption adapter and purpose-bound to the notification record. APNs payloads carry only generic presentation text and opaque record/destination identifiers; sensitive data never enters URLs, logs, metrics labels, traces, or badges.

The server interface is intentionally small: record typed intents, list a member's bounded inbox page, change that member's read state, delete that member's visible record, and dispatch bounded due channel work. Domain producers must record intents in the same transaction as authoritative mutations when such a transaction exists. Provider and occurrence processors use idempotent claims so a crash between processing and dispatch cannot duplicate user-visible records.

Existing specialized outboxes migrate incrementally behind this module with compatibility reads until no released client depends on their old behavior. The Alerts tab reads the Notification Center store rather than APNs history or the local conflict-only store. Notification taps resolve typed destinations only after normal authorization checks.
